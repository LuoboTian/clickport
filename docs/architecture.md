# 架构提案 · 待技术评审

SwiftUI 设置与菜单栏状态菜单 + AppKit 系统交互 + Finder Sync 扩展。此为提案，不代表已验证所有系统接口。

职责：扩展只构建菜单与提交明确目标；主应用执行动作、管理配置和授权。领域层负责菜单校验、目标解析、文件命名和结果汇总；系统适配层封装文件系统、应用启动、剪贴板、共享与权限。

跨进程共享配置、消息机制和存储方案通过技术验证后以 ADR 确定。消息需校验动作标识、目标和来源，不把任意命令字符串作为协议。避免权限较弱进程请求执行超出用户操作的动作。

主应用以授权书签访问用户目录；执行范围以具体目标为准。菜单不扫描磁盘内容。配置版本化，迁移失败保留原文件。导出配置不带凭证及可复用授权。环境变量可能含秘密，不写诊断日志。

拟定目录（批准开发后创建）：apps/macos、extensions/finder、modules/domain、modules/platform、tests/unit、tests/integration、tests/ui、scripts、docs/adr。

开发前验证：扩展签名/App Group/激活；空白与选中项目标；桌面/外置卷/云盘；应用参数与新实例；有效 Office/iWork 模板；隐藏菜单栏图标后的设置恢复；最低系统与发行渠道。技术实验也需要评审批准，不自动开始。

发行渠道、正式标识、存储、更新机制及第三方依赖尚未决定。当前没有引入第三方源码；未来复用必须满足授权并保留必要声明。

## 后续扩展约束

按 [Roadmap](roadmap.md) 预留动作与菜单解耦的设计：稳定动作标识、适用目标与多选能力、权限/配置、执行与结果格式。V1 仅为 FR-01–FR-13 提供必要实现，不建设脚本/插件平台。快捷指令、官方新增动作及 AI 能力分别评审与验证，当前未授权实验或实现。
