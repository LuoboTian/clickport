## CI 阶段设计

- 当前文档阶段：人工检查内部链接、需求编号、禁止标识、草图与 PR 范围。
- 批准工程搭建后：PR 运行文档检查、格式/静态检查、编译、单测及适用集成测试；固定 Xcode/SDK 与 runner 版本。
- 无签名编译只能证明编译能力；不能代替扩展安装与权限验证。
- 签名实机/UI 测试进入受控环境；外部 PR 不获得证书或发布秘密。
- release 标签触发已批准的构建/签名/公证/产物校验；发布需要验收批准。上传和发布不混同本地构建。
- 失败阻止合并；不稳定测试必须跟踪责任与修复期限，不长期忽略。

PR 必查：需求与测试映射、失败提示、配置迁移、无敏感信息。发布必查：兼容矩阵记录系统/芯片/版本/结论；已知限制、回滚与数据保留方案、安装升级、支持语言。日志及测试产物检查隐私后再上传。
