批准开发后的建议顺序：扩展与目标/权限 → 应用与新建/路径 → 隐藏/删除/共享/目录 → 状态菜单和菜单布局 → 配置/语言/发行配套。分批交付不减少 1.0 范围。

每项需求状态：草稿 → 已澄清 → 已批准 → 开发中 → 待测试 → 已验收。变更必须说明范围、UI、测试和进度影响，并重新批准受影响部分。

完整范围以 [需求与验收](requirements.md) FR-01–FR-13 为准，P0 与 P1 均保留，不因分批交付而删减。

| 工作包 | 内容 | 关联需求 |

| 新建与目录入口 | 文件模板、导入模板、常用目录管理 | FR-07–08 |
| 菜单配置 | 第一层快捷操作、分组排序、保存/放弃、配置校验；任意嵌套、标题和图标编辑已暂缓 | FR-09 |

当前按 [需求与验收](requirements.md) 的上下文、模板来源、快捷入口和导出边界实施。历史问题和授权保留在 [评审记录](reviews/001-v1-review.md)；具体通过证据、失败和未验证项统一见 [V1 验证清单](development/v1-verification.md)。当前关键缺口包括高级启动异常边界、受管理环境下的 AirDrop、iWork 原应用验收、兼容性与正式发行验证。macOS 15 为当前部署目标，首验 Apple Silicon；尚未实测的平台不标记兼容。

## 后续扩展路线 · 不计入第一版验收

| 阶段 | 候选内容 | 进入条件与验收重点 |
| --- | --- | --- |
| E1 官方新增动作 | 批量重命名、压缩、图片格式转换 | V1 核心场景验收后，按实际需求逐项立项；预览变更、冲突处理、进度、取消与部分失败规则明确 |
| E2 用户工作流 | 接入 macOS 快捷指令，用户选择指令并将选中文件传入 | 先批准技术验证，确认传参、多选、授权、取消/超时和结果反馈，再评审配置入口 |
| E3 高级用户扩展 | 脚本或插件机制 | 有明确需求后单独评审执行权限、来源信任、参数边界、超时、诊断、禁用及配置分享；不默认开放任意命令 |
| 独立候选 | AI 文件处理 | 单独确认使用场景、本地或云端处理、上传授权、费用及结果确认；不作为 V1 依赖，也不预先新增设置栏目 |
| 其他候选 | 复制/移动、可撤销操作 | 单独定义目标、重名覆盖、跨卷行为和撤销能力边界后再排期 |

## 架构预留 · 仅设计约束

动作与菜单展示解耦。动作定义预留稳定标识、名称/图标、适用对象与多选能力、所需权限及配置、执行入口、进度/取消和结果格式。第一版只实现当前需求实际需要的部分，不提前搭建插件平台。

新增动作优先复用现有分组和快捷操作配置。菜单层级编辑只改变入口结构，不等于执行脚本或增加新能力。每项后续能力需补充独立需求编号、设计与验收标准，并获范围授权后开始实现。

## 本轮决策 · 2026-09-29

用户确认 V1 边界并授权技术验证。首版暂缓任意嵌套、标题和图标编辑；支持空白处打开当前目录及具体应用/目录/模板快捷入口。Office/iWork 用户导入模板。

发行顺序建议：V1 DMG → 后续自有 Homebrew tap/cask → 单独评估 App Store。DMG 正式发行需签名公证；Homebrew 不能代替扩展和权限授权；App Store 单独评估沙盒及更新机制。Swift 6 + SwiftUI 已确认；macOS 15.0+ 为最低系统建议，须实机验收。

2026-09-29 发行范围确认：用户选择 DMG + Homebrew，稳定后再上传或发布到 GitHub。App Store 暂不安排。本机开发证书仅用于本地实验；证书、私钥、签名身份及凭据不得写入仓库。Homebrew 分发依赖之后明确批准的稳定下载地址，当前不上传。
